# HEVC / H.264: согласование и проверка

## Контракт DSXP v1

Framing не меняется: control JSON `0x00`, Annex-B video `0x01`, PCM `0x04`, video timing `0x05` непосредственно перед своим AU.

Клиент добавляет в hello:

```json
{"magic":"DSXP","version":1,"codecs":["hevc","h264"],"preferredCodec":"hevc"}
```

- `codecs` перечисляет доступные декодеры клиента, а не рекламируемую совместимость всех Android-устройств.
- `preferredCodec` — предпочтение, а не приказ серверу отправить неподдерживаемый формат.
- При общем предпочтительном кодеке выбирается он; иначе HEVC, затем H.264 из пересечения.
- Отсутствие `codecs` означает старый клиент и прежний HEVC.
- Пустое/невалидное объявление или отсутствие общего кодека — ошибка, не молчаливое включение HEVC.
- Успешный ack содержит фактически выбранный `codec`: `hevc` или `h264` и предшествует видео нового потока.
- Старый сервер без поля `codec` трактуется как HEVC. Неизвестное имя из нового ack нельзя выдавать за HEVC.
- Изменение выбора клиента требует нового согласования и пересоздания декодера; форматы одного потока нельзя смешивать.

На ключевых кадрах сервер вставляет parameter sets: HEVC — VPS/SPS/PPS, AVC — SPS/PPS. AVC IDR имеет NAL type 5. Длина NAL-header в контейнерном представлении читается из format description, start codes выходного Annex-B не являются длинами NAL.

## A/B без обещаний выигрыша

Цель — определить, даёт ли AVC меньшую задержку на конкретной паре Mac/планшет. Название кодека само по себе этого не доказывает.

1. Сохранить одинаковые транспорт, разрешение backing, логические размеры, запрошенные FPS, битрейт и частоту панели. Для исходного опыта: USB, 2944×1840, запрос 120 fps, 120 Mbit/s. Не включать одновременно `DS_LOWLAT` и другие экспериментальные параметры.
2. Подтвердить в ack/log фактический кодек. Дождаться первого декодированного кадра и синхронизации часов, не снимать старые застывшие значения.
3. Использовать одинаковый движущийся источник, подтверждённый на дисплее Mac. Провести HEVC → AVC → HEVC, не один скриншот каждого варианта.
4. Собрать серию значений при движении: callback SCK → releaseOutputBuffer, encode-output → releaseOutputBuffer, decoder feed → output; одновременно записать число кадров, ошибки, реконнекты и изменения битрейта ABR.
5. Отдельно проверить читаемость текста, звук, ввод, отключение, повторное подключение и возврат HEVC. Быстрый codec round-trip тест не заменяет тест на планшете.

### Границы метрик

`cap` сейчас ставится при входе в callback SCK, а не в момент реального захвата изображения. `enc` — callback готового access unit. Android-метрика заканчивается при передаче output buffer на рендер, **не при физическом появлении пикселя**. Путь input transit заканчивается при разборе сообщения на сервере, не при CGEvent-инъекции или обработке приложением.

Сопоставление telemetry по FIFO может терять точность, если энкодер/декодер пропустил кадр; для строгих выводов нужны идентификаторы/PTS сквозь callbacks, корректная обработка drops и серии измерений. Разность двух средних из оверлея не доказывает точное местонахождение очереди. Полная touch-to-photon задержка требует отдельного эксперимента.

Пока A/B на устройстве не выполнен, AVC считается альтернативным кодеком, **не подтверждённой оптимизацией**. Совместимость Samsung/Xiaomi остаётся непроверенной до испытаний конкретных устройств.
